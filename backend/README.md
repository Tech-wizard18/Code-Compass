# CodeCompass 🧭
An AI-powered learning companion for exploring open-source codebases through natural language chat.

## What it does
Students paste a public GitHub repo URL. CodeCompass clones it, parses the source code into meaningful chunks (by method/class level using AST parsing), embeds those chunks into a vector database, and lets the student ask natural language questions like "how does login work?" or "explain this method" — getting answers grounded in the actual code with exact file and line references, generated by a locally-running LLM. Conversations are saved per user, so students can revisit past chats about any repo, and everything is protected behind proper authentication.

## Tech Stack
- **Backend:** Java 17, Spring Boot 3
- **Code Parsing:** JavaParser (AST-based chunking at method/class level)
- **Repo Cloning:** JGit
- **Embeddings:** Ollama (`nomic-embed-text`, 768 dimensions) — runs completely locally
- **LLM (answer generation):** Ollama (`llama3`) — runs completely locally, no external API calls
- **Vector Database:** PostgreSQL 16 + pgvector extension
- **Authentication:** Spring Security + JWT (stateless, role-based)
- **Build Tool:** Maven

## Architecture

**Indexing a repo:**
GitHub URL
→ JGit Clone
→ FileFilterService (skip .env, secrets, node_modules)
→ JavaChunkerService (AST parsing → method/class chunks)
→ EmbeddingService (Ollama nomic-embed-text → 768-dim vectors)
→ PostgreSQL + pgvector (persistent storage)

**Answering a question:**
Student Question
→ EmbeddingService (embed question)
→ pgvector cosine similarity search
→ Top 5 relevant chunks retrieved
→ Prompt built with real code + question
→ Ollama llama3 generates grounded answer
→ Answer + citations + question saved to conversation history

**Authentication:**
Register/Login → password hashed (BCrypt) / verified
→ JwtService issues signed JWT (30-day expiry, includes username + role)
→ JwtAuthFilter validates JWT on every subsequent request
→ SecurityContext carries verified identity into every controller

## Privacy First
- Only **public repos** are supported — no private code ever processed
- Embeddings **and** LLM inference run **locally via Ollama** — your code never leaves your machine
- Sensitive files (`.env`, `secret`, `credential`, `password`, `.pem`, `.key`, `api_key`) are automatically filtered and never read or processed
- No PII stored beyond what's needed for citations (file path, line numbers) and account login (hashed password only — plaintext passwords are never stored)

## Supported Languages
- **Java** — Spring Boot projects (AST-based chunking via JavaParser)
- **JavaScript / TypeScript / JSX / TSX** — React + MERN stack projects (file filtering supported, JS chunking coming soon)

## API Endpoints

| Method | Endpoint | Auth Required | Description |
|--------|----------|----------------|-------------|
| GET | `/api/health` | No | Health check — confirms backend is running |
| POST | `/api/auth/register` | No | Create a new account (defaults to `USER` role) |
| POST | `/api/auth/login` | No | Log in, receive a JWT |
| POST | `/api/repos/index` | Yes | Clone, parse, embed and index a public GitHub repo |
| POST | `/api/search` | Yes | Search indexed chunks using natural language |
| POST | `/api/chat` | Yes | Ask a question, get an LLM-generated answer with citations, saved to conversation history |
| GET | `/api/conversations` | Yes | List the logged-in user's past conversations |
| GET | `/api/conversations/{id}/messages` | Yes | Get all messages in a specific conversation (owner-only) |

All protected endpoints require an `Authorization: Bearer <token>` header, obtained from `/api/auth/login` or `/api/auth/register`.

### Example: Register
```json
POST /api/auth/register
{
  "username": "sanjog",
  "password": "yourpassword"
}
```

### Example: Chat (start a new conversation)
```json
POST /api/chat
{
  "repoUrl": "https://github.com/spring-projects/spring-petclinic",
  "question": "how does owner search work?"
}
```

### Example: Chat (continue an existing conversation)
```json
POST /api/chat
{
  "repoUrl": "https://github.com/spring-projects/spring-petclinic",
  "question": "what does the Pet entity look like?",
  "conversationId": 1
}
```

### Example response
```json
{
  "answer": "The owner search functionality is implemented in the OwnerRepository interface...",
  "citations": [
    { "filePath": "...OwnerRepository.java", "name": "findByLastNameStartingWith", "startLine": 45, "endLine": 45 }
  ],
  "conversationId": 1
}
```

## Setup & Running

**1. Install Ollama and pull the required models:**
```bash
ollama pull nomic-embed-text
ollama pull llama3
```

**2. Set up PostgreSQL:**
```sql
CREATE DATABASE codecompass;
\c codecompass
CREATE EXTENSION vector;

CREATE TABLE code_chunks (
    id BIGSERIAL PRIMARY KEY,
    repo_url TEXT NOT NULL,
    file_path TEXT NOT NULL,
    chunk_type VARCHAR(50) NOT NULL,
    name TEXT NOT NULL,
    start_line INT NOT NULL,
    end_line INT NOT NULL,
    content TEXT NOT NULL,
    embedding vector(768)
);

CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(255) NOT NULL UNIQUE,
    password VARCHAR(255) NOT NULL,
    role VARCHAR(50) NOT NULL
);

CREATE TABLE conversations (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL REFERENCES users(id),
    repo_url VARCHAR(500) NOT NULL,
    title VARCHAR(255),
    created_at TIMESTAMP NOT NULL DEFAULT now()
);

CREATE TABLE messages (
    id BIGSERIAL PRIMARY KEY,
    conversation_id BIGINT NOT NULL REFERENCES conversations(id),
    role VARCHAR(20) NOT NULL,
    content TEXT NOT NULL,
    citations TEXT,
    created_at TIMESTAMP NOT NULL DEFAULT now()
);
```

**3. Configure application.properties:**
```properties
spring.datasource.url=jdbc:postgresql://localhost:5432/codecompass
spring.datasource.username=postgres
spring.datasource.password=your_password
spring.datasource.driver-class-name=org.postgresql.Driver
spring.jpa.hibernate.ddl-auto=none
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect

jwt.secret=your-long-random-secret-key-at-least-32-characters
jwt.expiration=2592000000
```

**4. Run the backend:**
```bash
mvn spring-boot:run
```

Backend starts on `http://localhost:8080`. Make sure Ollama is running (`http://localhost:11434`) before starting the app.
